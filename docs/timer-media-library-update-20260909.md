# 计时提醒与后台文件库更新（2026-09-09）

## 本轮交付

- Android 倒计时新增原生 AlarmClock 与私有接收器，后台提示音不依赖 JS 定时器；前台仍使用既有语音，旧提示不在回 APP 时补播。
- 正数计时独立发布系统计时通知，不再等待倒计时预约清理；区分用户主动划除和系统通知缺失，避免误停恢复。
- Android 运行时改为 1.1.4；已有 Build 7 / 1.1.3 不包含本轮原生实现。未自动 Build、OTA 或发布 iOS。
- 后台首页和设施教学的视频编辑由 YouTube 文本输入改成“本地上传 / 从后台现有云端存储选择”。设施图片和左右 GIF 使用相同入口。
- 新增 APP 维护 → 文件存储空间：搜索、分类、分页、改名、调整分类、归档与恢复。归档不删除磁盘文件；正在被内容引用的文件不能归档。
- 文件管理使用独立权限 app_maintenance.files.manage；首页或设施维护人员可在相应编辑流程上传/选用公开文件，不自动获得全部文件管理权限。
- 当前服务器的持久文件库是“后台现有云端存储”，没有另开第三方云账号、存储桶或付费服务。
- 图片/GIF 上限 12 MiB，视频上限 250 MiB。原始二进制上传，校验扩展名、MIME、文件签名、大小和安全路径；支持取消、进度、失败重试及重复点击保护。
- APP 与 Web 增加上传视频播放器，保留旧 YouTube 兼容播放。上传视频优先，但不会自动下载或转换旧 YouTube 视频。推荐 MP4（H.264/AAC）；MOV/WebM 的实际编解码支持取决于设备。
- 视频观看数据保持记录；修复旧视频换成新视频时混算时长，以及旧播放器迟到的播放/错误事件影响新视频的问题。

## 现有文件整理与隐私边界

- 只索引公开设施图片、GIF、教学视频、现有维护引用及明确的旧图片上传目录，不扫描用户头像、聊天附件、用户资料、凭据、数据库或整个磁盘。
- 从 constants/Equipments.js 和 NewMachines.js 明确引用的教学图片/GIF 生成种子：121 条引用、116 个唯一文件，共 136,518,878 字节（55 GIF、56 JPEG、5 PNG）。
- 几个历史 .jpg 文件实际含 PNG 数据，导入副本使用真实扩展名/MIME；没有改动原图或像素。
- 服务启动复制种子到数据库旁的 media-library 持久目录，按 SHA-256 去重；再次部署不重复导入，也不覆盖管理员后来修改的名称/分类。
- 音频、私人文件及没有明确公开用途的文件未纳入本轮文件库。

## 安装包与真机验收边界

本机没有 Android SDK/JDK/adb，因此本轮未编译 Kotlin、未生成新 APK、未真机锁屏验收。此前 Build 7 原生编译成功不能作为新 1.1.4 原生代码已编译的证据。

中文后台仍为系统提示音，英文为既有短语音；没有擅自加入普通话替代粤语。通知/铃声音量、勿扰、锁屏隐私以及精确提醒权限必须由用户允许，程序不会绕过。

原生闹钟允许最多 10 秒系统投递容差，前台语音有效窗口保持 2 秒。系统“强行停止”或设备重启会使预约失效；用户需重新打开 APP 恢复未来阶段，不补过去的声音。没有新增自动启动或电池豁免。

新 Android 包至少真机验证：短倒计时前后台/锁屏半程与结束、暂停继续、放弃重开、正计时通知与实时秒数、通知点击返回、权限拒绝后授权、静音/用户主动划除、计时结束后日志保存。

## 服务器部署

外层 ZIP 包含 API、独立 Web 产物、公开素材种子、安装脚本和保护检查工具，不含 .env、凭据、用户数据或 node_modules。

安装脚本先校验依赖/代码/路径并备份，再更新代码；不删除旧 Web 资源、数据库或上传媒体。文件库默认位置为 DATABASE_PATH 同级 media-library，可用 MEDIA_UPLOAD_DIR 配置。大文件上传仅配置精确的 /api/admin/media/upload 路径，保留原 API 的权限与代理规则；未知上游、正则或包含文件的路由会停止，要求运维手动审查，不擅自绕过已有访问控制。

失败会尝试恢复应用代码及 Nginx 配置；数据库的新增兼容结构和已导入的公开素材保留，不属于完整数据库回滚。默认 API data 目录会在服务停止时备份，自定义外部数据目录需要沿用服务器自身备份策略。恢复阶段文件会保留，未做自动磁盘清理。

服务更新不会发布手机安装包，也不会增加 TestFlight 编号。必须先更新服务器，再构建包含本轮原生代码的 Android 1.1.4；不能把本轮原生修复当成 Build 7 的 OTA 交付。
