| 级别 | 已复现问题 | 修复位置与行为 |
| --- | --- | --- |
| P1 | 一个 AI 会话达到历史条数或容量上限后，结果入库反复失败，阻塞其他账号任务；重启恢复也可能失败 | `server/src/accountContinuity.js`：确定性容量错误不再阻止任务结束；保留可查询的回答，返回 `historyError`，继续处理队列。暂时数据库错误仍重试保存，不重复调用 AI。 |
| P1 | 目标／语言设置写入成功但回包丢失，随后本地新编辑可能被旧值覆盖 | `utils/accountSyncJournal.js`、`utils/goals.js`、`utils/accountPreferences.js`：持久化未确认批次，先确认原操作，再给后续编辑更新版本。真实多设备冲突的处理规则保留。 |
| P2 | AI 任务领取已提交，但连接在回包前断开，任务长期停留在 running | `server/src/accountContinuity.js`：保存领取意图，恢复时核对同一个任务的状态，然后调用 AI。 |

## 发布范围

运行代码的修复已纳入本次 Git 提交；v11 交付单独准备，详见 `docs/account-data-delivery-20260930-v11.md`。旧 v9/v10 部署文件、归档和 OTA 导出保留，不把修复偷偷写入已经封存的版本。

GitHub 推送不等于阿里 ECS 已安装，也不等于网页或手机 OTA 已发布。修复生效需要按 v11 交付说明部署和发布。AI 历史满额时回答仍能通过任务结果取回，但该会话的历史容量限制本身并未取消。
