# Outdoor Fit 存储与加载优化方案

日期：2026-09-24。依据当前仓库、已确认的阿里云部署输出和用户提供的配置；不是线上性能测量报告。

## 先做的决定

1. 正式使用的 RDS Serverless 关闭自动启停，保留弹性伸缩和现有 RCU 范围。控制台配置尚未修改。
2. 保留现有 ECS 文件存储，先解决启动请求、图片缓存和缩略图，不因当前反馈直接升级带宽或购买 CDN。
3. RDS 保存结构化业务数据和媒体索引；头像、聊天图片后续分批从数据库转为文件，保留权限与旧客户端兼容。
4. 本轮 Android OTA 只包含联络页回退方式、一次重复启动校验的去重、收藏卡片图片缓存与占位优化。未改后端、数据库或已有文件。

## 现状：图片并非都在数据库

| 内容 | 当前存储与读取 | 建议去向 |
| --- | --- | --- |
| 媒体库图片、GIF、视频、附件 | ECS `/opt/outdoor-fit/production/state/media-library`；RDS 保存名称、路径、大小、类型、校验值和删除状态等 | 继续 ECS；增加列表缩略图，保留原文件；以后按需要迁移 OSS |

源码依据：`server/src/mysqlMediaLibrary.js`、`server/src/appMysql.js`、`server/src/mysqlMediaStorageSeed.js`、`constants/Equipments.js`。实际线上文件内容未在本轮重新扫描。

## 慢在哪里，以及证据的界限

### RDS 自动暂停

用户确认使用 Serverless 并开启自动暂停。阿里云说明，无连接达到条件后可自动暂停，后续连接触发恢复通常需要约 6–40 秒，恢复期间数据库不可用。因此，隔一段时间首次进入时等待是有依据的风险，但开启开关本身不能证明每一次慢都由唤醒导致。应用已有连接和前台轮询时，数据库也可能一直没有暂停。

尤其是当前部署配置每 30 秒调用 `/api/health`，接口每次执行 `SELECT 1`，连接池也会复用连接。因此健康运行的部署会持续访问数据库，很可能根本没有进入自动暂停。必须结合 RDS 的实际启停记录判断；关闭开关是正式服务的稳定性配置建议，不是已证明的本次延迟修复。依据为 `deploy/aliyun-production/compose.yaml` 的 healthcheck 和 `server/src/appMysql.js` 的健康接口，线上是否有另行改动尚未重新读取。

当前恢复登录会等待服务器验证，客户端请求有超时限制。数据库处于恢复过程中时，可能出现等待或请求超时；将图片放 ECS 并不能消除这条依赖。

操作路径：RDS 实例 → 配置信息 → 调整弹性设置 → 高级设置 → 自动启停 → 关闭 → 确定。保留弹性伸缩，暂不随意提高 RCU。关闭后空闲时也会有计算费用，存储费用仍然存在。通过任务中心的启停记录，对照慢请求时间判断实际影响。

来源：[阿里云 RDS MySQL Serverless 官方说明](https://www.alibabacloud.com/help/zh/rds/apsaradb-rds-for-mysql/rds-mysql-serverless)。

### 启动和请求

- 本地恢复会话后原来会立即重复调用一次 `/users/me`。本轮只移除成功恢复后的这一次重复请求，保留初次服务端校验、前台复查、定期复查及账号删除处理。
- 初次校验仍可能等待网络或 RDS；本轮不能保证消除启动白屏或所有启动延迟。
- 后端账号检查涉及多次查询；数据库适配器每次取得连接都会重新设置字符集和时区。可以进一步评估连接生命周期内初始化、减少重复读取，但必须保留连接复用后的正确状态、账号权限和撤销校验。
- 首页存在重复获取运动记录的路径，后续可以合并并发消费者的同一次读取。以上后端和首页调整本轮尚未实施。

### 收藏图片与带宽

用户提供 ECS 带宽上限为 200 Mbps。这是上限，不是手机的实测速度；不能据此认定传输没有瓶颈，也没有证据要求立即升级。页面还会受图片尺寸、跨网线路、手机解码、缓存命中以及请求等待影响。

收藏卡片可能用后台 URL 覆盖内置图片。部分内置原图约 1200 × 1600，接近 1 MB，用于小卡片时仍有解码成本。原来的原生图片组件也可能缓存，本轮是明确采用内存/磁盘缓存与本地占位，并允许按显示尺寸降采样解码，不是宣称此前完全没有缓存。

本轮没有重新压缩图片，也没有生成服务器缩略图，因此首次远程下载的原文件字节数不会凭空减少。缓存可能被系统清理，首次打开仍受网络影响。

## 目标分工

| 层 | 保存的内容 | 体验与可靠性要求 |
| --- | --- | --- |
| RDS | 账号、密码哈希、权限、同意记录、运动/学习记录、科研事件、消息文字、内容目录、媒体索引及关系 | 数据库不只保存“重要用户资料”，需要查询和事务的业务关系仍适合保留；避免把大图片放进常用 JSON 返回 |
| ECS 持久目录 | 原始文件、图片缩略图、公开视频与私有附件；按权限类别分开管理 | 不放在容器临时文件层；原文件有独立备份；保留现有 URL 和访问检查 |
| 手机 | 内置基础素材、公开图片缓存、可恢复的目录缓存；用户缓存按账号隔离 | 已缓存图片优先显示，后台更新内容；切换账号和退出遵守原有清理规则；私有内容不能因缓存绕过权限 |
| 可选 OSS / CDN | OSS 保存原文件、衍生图或异地副本；CDN 用于适合公开分发的教学媒体 | 先确认流量、费用、地域和延迟收益，再接入；私有源站认证不能代替用户授权 |

## 分阶段实施，不中断旧版本使用

### 阶段 1：当前交付

- 用户在阿里云关闭自动启停。
- 发布 Android Build 17 对应的 Performance v2 OTA。
- 联络页使用与“关于此程序”一致的导航返回和 Android 返回处理，去掉上一轮 Contact 专属的返回和手势改动。
- 收藏卡片显示本地占位，使用明确的内存/磁盘缓存和降采样；图片失败后下一次进入可重试。
- 比较同一手机、同一网络下的首次启动和再次启动。真机过渡动画和实际耗时尚未在本轮验证。

### 阶段 2：缩略图与读取优化

1. 保留原文件，为器材卡片生成带版本标识的缩略图。可从 320–480 像素边长起步，按裁剪、清晰度和手机像素密度选择；30–100 KB 可作为评估目标，不是所有图片的硬性大小。
2. 在目录 API 增加可选 `thumbnailUrl`，新客户端优先缩略图，旧客户端继续读取 `imageUrl`。详情页和下载保留原图。
3. 分批处理现有图片，生成成功后才更新索引；失败保留原引用，避免出现空白卡片。
4. 公开目录采用带版本和有效期的缓存，先显示已缓存目录，再更新；不使用这一方式绕过私人数据的登录和权限验证。
5. 分别测量 API 等待、文件传输和手机渲染后，再优化账号接口、首页重复读取及连接初始化。不为这个规模先引入额外 Redis 服务。

### 阶段 3：头像和聊天图片迁移

1. 先提供兼容读取：新文件引用和旧 base64 都可读取。Android/iOS/网页都未兼容前，不能直接改变旧响应字段含义。
2. 新上传写入按权限隔离的文件位置，校验大小、类型和内容哈希后保存数据库引用。失败时清理未引用的临时文件，保留可重试状态。
3. 旧数据按批次复制，逐项核对大小与哈希，再通过事务保存引用。每批有迁移记录，支持继续执行与回退。
4. 聊天图片通过受保护接口返回，只允许会话成员获取；撤回、删除、注销等操作沿用原语义。不能把它们转换成长期公开 URL。
5. 保留旧数据和备份至兼容期结束，并确认所有相关客户端已升级后，再另行清理旧 base64。先迁移引用，不先删除历史内容。

这一阶段尚未修改线上数据或应用接口。

### 阶段 4：按需要接入 OSS / CDN

规模或实际跨地区延迟证明有收益时，再将原文件和衍生图迁入 OSS，并为公开内容接入 CDN。先复制和校验，再切换来源，保留旧 URL 的兼容入口；不要一次性改掉旧客户端保存的链接。

OSS 可生成缩略图、调整质量和转换格式；CDN 可缓存静态内容。当前客户端直连视频支持 MP4/MOV/WebM/M4V，但不直接支持 HLS，且对带签名参数的视频 URL 有限制。因此，私有签名 URL 或 HLS 需要对应的客户端/服务端适配，不能只替换数据库链接。

来源：[OSS 图片处理](https://www.alibabacloud.com/help/en/oss/user-guide/overview-17)、[OSS 与 CDN 配合](https://www.alibabacloud.com/help/en/oss/user-guide/cdn-acceleration)。

## 现有访问规则必须保留

- 器材图片当前直接读取 ECS 文件；公开媒体接口还会检查文件、文件名和删除状态。现有公开视频已有缓存及 Range 支持，应在这些能力上改进。
- 管理员附件下载需要授权，使用私有、不可共享缓存的响应。不能将整个媒体目录通过 Caddy 无条件公开来“提速”。
- 当前公开图片/视频长期缓存有过期时间；服务器删除后，旧客户端缓存不一定立即消失。未来需要立即撤销的内容，应独立设计较短缓存和失效机制。
- 当前“归档”只影响媒体列表和选择，不禁止直接访问；旧器材图片接口也不检查数据库软删除。后续应明确归档、软删除和撤销访问各自的行为，不能把它们视为同一功能。
- 原文件与缩略图使用不同的版本化地址，内容改变时更新地址，避免长缓存展示旧图片。
- ECS 同盘副本不是完整容灾。文件备份应放到独立位置，并保存与数据库备份对应的媒体清单；RDS 备份不包含 ECS 文件。

## 验收记录建议

用同一设备、同一网络分别记录闲置后第一次和紧接着的第二次访问，至少区分：

| 指标 | 用途 |
| --- | --- |
| 启动至显示可用首页的时间 | 区分初始认证和页面渲染；与 RDS 启停记录对照 |
| `/users/me`、内容目录接口耗时 | 区分数据库或接口等待 |
| 收藏图片首次下载大小、响应等待、下载耗时 | 判断是否需要缩略图、网络优化或 CDN |
| 已访问收藏页再次进入的显示情况 | 检查缓存及本地占位是否有效 |
| 联络页进入和返回，包含键盘打开/关闭 | 确认 Android 真机过渡符合“关于此程序”的体验 |
| 老版本链接、私有图片权限、附件下载 | 确认迁移没有破坏兼容性或泄露文件 |

本轮未取得线上 P50/P95 延迟、缓存命中率或手机性能轨迹。后续应依据这些结果决定下一阶段投入，而不是承诺所有内容都能首次“秒开”。
