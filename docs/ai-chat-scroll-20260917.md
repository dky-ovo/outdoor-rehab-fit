# AI 聊天页底部定位与历史滚动修复（2026-09-17）

## 问题与原因

旧列表在每一次内容高度变化时执行带动画的scrollToEnd，在每一次布局变化时再次滚到底。历史恢复、长篇器材及中医说明、虚拟列表高度校正、键盘收放均可能触发这两条路径。上翻时仍被拉回底部，不是聊天记录丢失。

## 修改范围

- 使用倒置的聊天列表，最新消息位于偏移0；首次显示不必测量全部80条长历史后再从顶部滚到底。
- 只对展示列表使用倒序副本。原始messages、AsyncStorage持久化及发给AI的上下文仍保持从早到晚，回复及推荐内容不改动。
- 首次进入、重新进入、主动发送文字/照片以及照片识别确认时，无动画定位最新消息。
- 原生平台删除无条件onContentSizeChange/onLayout滚到底行为。上翻时使用可见消息锚定，不启用原生自动动画阈值；迟到回复和键盘变化不主动拉回。
- 用户自己回到底部后解除历史锚定，新消息自然在最新端显示。
- 思考指示仍显示在最新消息下方，使用倒置列表的ListHeader；上下留白对应倒置调整，其他气泡、图片、输入栏和设施入口不变。
- 网页版仅在明确插入新消息前保存一次位置与高度快照，并在下一次内容测量时按总高度差进行一次无动画补偿；已由浏览器锚定时不重复补偿。旧历史恢复、普通重新测量不会自行触发滚动。
- 网页滚轮、触摸、拖动、视口大小或账号/语言/焦点变化会取消未完成的补偿；没有计时器、重复重试或Observer。补偿只针对一次新消息插入，不持续追踪后续图片高度变化。
