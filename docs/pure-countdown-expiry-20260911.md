# 纯倒计时及后台结束通知检查（2026-09-11）

## 用户要求

倒计时只用于计时，不再弹出运动记录；检查安卓后台已经有语音、但最后显示停在 5 秒的问题。

## 定位与修复

1. **结束仍弹记录的原因确定**：`ActiveSessionContext` 原先自然到时和提前结束都会创建 `pendingSummary`，计时页会嵌入运动总结；悬浮计时器还会自动跳转该总结。现改为独立的 `completed` 状态，不创建运动记录。完成语音也不再依赖总结对象。
2. **最后 5 秒卡住尚无现场日志，不能确认唯一根因**：Android 运行通知此前每秒使用 `startForeground` 重发静态秒数，同时多次触发通知取消、展示标识和偏好写入。最后阶段又与语音准备、JS 同步交错，旧秒数通知可能残留。现合并同一秒重复刷新；运行帧仅更新同一通知，前台服务类型只在实际变化时更新；展示标识按计时身份和阶段复用。
3. 到时原生计时与通知明确进入完成阶段：使用独立通知 ID 显示固定 `0:00`，移除旧运行卡；语音播完清理结束卡。保留已奏效的应用自带粤语／英文媒体播放，不改为系统铃声。
4. 旧 JS 通知更新不能覆盖仍由原生服务管理的计时，或在原生完成后重建同一计时的旧秒数。

## APP 流程

- 自然到时：停止计时 → 当前页显示 `0:00 / 计时结束` → 可点“再次开始”；不生成日志，不自动计入目标进度。
- 提前结束：仅确认结束倒数，不进入运动总结，不播放未来的到时提醒。
- 暂停、继续、放弃保持现有操作；放弃及重新开始使用不同计时身份，避免旧提醒影响新计时。
- 进入手动记录：完成的倒计时不再被视为活动计时冲突，手动记录仍从原入口独立填写和保存。
- 后台恢复：依据截止时间归零，不补播过期语音、不弹运动记录。
- 已完成计时隐藏悬浮球；点击与当前计时 ID 一致的通知可返回已完成页；旧通知不打开另一轮计时。
- 旧版本已填写但未保存的记录草稿不删除；旧倒计时草稿只通过用户显式点击恢复，不再自动弹出。
- 完成后重进页面，再次开始保留原定时长，不误用默认 30 分钟。

## 发布与限制

- 本轮未调用 EAS Build、未发布 OTA、未修改服务器或数据库。已有 Build 11 APK 与部署 ZIP 均保持原样，不包含此次修改。
- Android 原生服务和通知逻辑已变更；`app.config.js` 将旧 runtime 升为 `1.1.8`，保留发布项目和现有签名配置。必须重新 Build 并覆盖安装才能验证本轮安卓原生修复，不能只给 Build 11 发 OTA。
- 本地没有连接故障手机，也没有可用的 Android SDK 编译／设备环境；原生契约测试是源码检查，不替代 Kotlin 编译或 Android 系统 UI 实测。不能保证所有厂商在锁屏／省电下都无问题。
- 真机复核：中文和英文分别设 1 分钟，剩 10 秒锁屏，观察 5→0；结束语音应只播放一次、运行通知不残留，播完结束卡消失；解锁回 APP 应为结束状态且无记录弹窗。然后重复开始／暂停／继续／提前结束／放弃，并测试 5 分钟较长锁屏。
